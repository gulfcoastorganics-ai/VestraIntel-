# v0.6 Opportunity Graph Expansion

## Goal

v0.6 converts an anomaly into a ranked research plan. The engine asks: **which missing evidence edge is most likely to remove a blocker or materially change the commercial decision?**

It does not automate claimant contact, claim filing, asset purchases, powers of attorney, legal representation, CAPTCHA bypass, or entitlement decisions.

## New persistent object: `research_tasks`

Each task stores:

- anomaly/entity/opportunity provenance;
- task type and target identifier;
- expected graph edge (for example `assigned_to`, `successor_of`, `controlled_by`);
- authoritative source and access mode;
- expected information uplift;
- priority score;
- blockers the task can resolve;
- prerequisites and task-specific blocks;
- analyst state (`pending`, `in_progress`, `completed`, `dismissed`, `blocked`, `stale`);
- optional result JSON for whitelisted read-only API execution.

Completed/dismissed/in-progress analyst decisions survive replanning. Tasks that are no longer justified by the current anomaly graph become `stale` rather than being deleted.

## Priority model

The queue combines:

- anomaly severity;
- current actionability;
- evidence confidence;
- expected information uplift;
- effort penalty; and
- access-friction penalty.

This score is a **research-priority score**, not a probability of recovery or legal entitlement.

## Missing-edge task families

### Corporate history

When an entity has an official Companies House company number, v0.6 can plan:

- company profile;
- filing history;
- officers;
- persons with significant control (PSC); and
- insolvency information.

These are read-only official API calls and require a Companies House API key. Results are evidence pivots only. An officer or PSC match is never treated as proof that the person owns an unclaimed asset.

### Patent/IP chain

Patent anomalies can plan:

- USPTO assignment lookup;
- current status/maintenance re-check; and
- patent-family/continuation review.

USPTO Open Data Portal access is account-gated in 2026. v0.6 generates these tasks but does not bypass login or fabricate API access.

### Bankruptcy successor chain

Bankruptcy-held funds anomalies can plan:

- court record verification through the permitted court interface/export; and
- documentary successor-chain research.

Federal bankruptcy courts publish procedures recognizing successor claimants in circumstances such as assignment, purchase, merger, acquisition, or succession, but require documentation sufficient to establish the chain. The planner therefore treats the chain as a hard evidence problem rather than an inferred identity match.

### Royalty reconciliation

Royalty anomalies can plan:

- authorized MLC recording/work metadata lookup;
- SoundExchange public rightsholder/creator status lookup; and
- a reconciliation report.

This lane is intelligence/reconciliation only. The planner never treats third-party discovery as ownership of royalties.

### Lapsed technology

A patent-expiration anomaly can plan:

- current USPTO status re-check;
- assignment-chain research;
- family review; and
- market/procurement relevance research.

This prevents a maintenance-fee expiration notice from being mistaken for a complete freedom-to-operate determination.

## Read-only execution boundary

`fia task-execute <id>` only auto-executes these Companies House Public Data API reads:

- `companies_house_profile`
- `companies_house_filing_history`
- `companies_house_officers`
- `companies_house_psc`
- `companies_house_insolvency`

All other task types remain manual, credential-gated, enrollment-gated, CAPTCHA-gated, or legal-review tasks.

## CLI

```bash
fia pipeline
fia plan
fia research-task-types
fia tasks --min-priority 65
fia task 1
fia task-state 1 in_progress
fia task-execute 1
```

## API

```text
GET /api/research-task-types
GET /api/research-tasks
GET /api/research-tasks/{task_id}
```
