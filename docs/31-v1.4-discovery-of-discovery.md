# v1.4 — Discovery of Discovery

## Objective

v1.4 extends FIA from *dataset discovery* to *portal technology discovery*.

The engine can now take URLs already surfaced by source mining (or explicit analyst-provided URLs), reduce them to portal origins, and perform a bounded read-only fingerprint to answer:

- Is this a CKAN catalog?
- Is this a Socrata/SODA portal?
- Is this ArcGIS Hub/Portal?
- Does it publish DCAT/RDF catalog metadata?
- Does it advertise a SPARQL endpoint?
- Does it publish RSS/Atom change feeds?
- Does it expose a machine-readable bulk-download surface?

A successful fingerprint creates a **connector proposal**, not an active connector. The proposal must still be approved by an analyst.

## Discovery chain

```text
official catalog mining
      ↓
dataset candidate
      ↓
landing/resource/endpoint URLs
      ↓
origin extraction + host deduplication
      ↓
bounded read-only fingerprint
      ↓
portal candidate
      ↓
connector proposal
      ↓
approved / watch / rejected
```

This creates a second discovery layer: a single catalog candidate can reveal a previously unknown agency open-data portal, which can then become a new source ecosystem after review.

## Supported fingerprint families

### CKAN

Passive markers are combined with a GET request to the standard read-only Action API `status_show` endpoint. Confirmed CKAN portals receive a proposed connector using `package_search` plus the recently-changed activity endpoint.

### Socrata / SODA

FIA identifies Socrata/SODA markers passively. It deliberately does not attempt a SODA3 dataset query during fingerprinting because current SODA3 queries can require an application token or authenticated user. The resulting connector proposal records that credential requirement for later review.

### ArcGIS Hub / Portal

FIA can test public, read-only search surfaces including ArcGIS Portal `sharing/rest/search` and the Hub OGC-style Search API landing route. Only public search behavior is fingerprinted.

### DCAT

FIA recognizes DCAT vocabulary markers and advertised RDF serializations such as Turtle, RDF/XML and JSON-LD. DCAT proposals retain discovered catalog URLs for a later RDF metadata adapter.

### SPARQL

FIA probes a SPARQL endpoint **only if the seed page explicitly advertises a same-host SPARQL URL**. The probe is a bounded read-only query:

```sparql
SELECT * WHERE { ?s ?p ?o } LIMIT 1
```

No UPDATE request is implemented or permitted by the connector proposal.

### RSS / Atom

FIA detects standard feed autodiscovery links and feed content types. These are proposed as change-monitor connectors, useful for portals that announce new datasets or notices through syndication rather than a catalog API.

### Generic bulk download

If a page advertises multiple machine-readable file links (CSV, TSV, JSON, ZIP, XLSX, Parquet, RDF serializations, etc.), FIA can propose a bulk-file monitor even when no named portal technology is recognized.

## Seed generation

`portal-discover` can use:

1. explicit analyst URLs via `--url`; and/or
2. URLs derived from FIA source candidates.

Candidate seeding uses:

- landing URLs;
- metadata URLs; and
- bounded endpoint/resource/download URLs already present in the catalog's raw metadata.

Origins are deduplicated before probing, so a catalog containing hundreds of datasets on the same agency host does not cause hundreds of identical portal fingerprints.

## Connector priority

Each portal candidate receives a 0–100 `connector_priority_score` based on:

- fingerprint confidence;
- useful machine capabilities (search, RDF query, catalog metadata);
- change/delta capability;
- public read-only access; and
- the highest source-candidate asset signal that led FIA to the portal.

This is a **connector-build priority**, not an asset-value estimate.

## Analyst states

```text
discovered
approved
watch
rejected
archived
```

State survives rediscovery. Metadata, evidence and scores may refresh without resetting a prior analyst decision.

## Commands

```bash
fia portal-technologies

# Fingerprint portals inferred from discovered dataset candidates.
fia portal-discover

# Add explicit seeds as well.
fia portal-discover \
  --url https://example.gov/open-data \
  --url https://data.example.org

fia portal-candidates --min-score 60
fia portal-candidate 12
fia portal-candidate-state 12 approved
fia portal-discovery-runs
```

## Safety and access boundary

Portal discovery is intentionally conservative:

- HTTP(S) GET only;
- no login attempts;
- no form submission;
- no CAPTCHA or access-control bypass;
- no SPARQL UPDATE;
- no Socrata credential workarounds;
- bounded response parsing;
- bounded same-host SPARQL probing only when explicitly advertised;
- connector proposals require analyst approval before becoming ingestion work.

The feature discovers public data infrastructure. It does not assert that data hosted on a discovered portal may be commercially reused, nor that any asset discovered through it is claimable by the operator.
