# v0.3 Entity Resolution and Evidence Graph

## Purpose

The v0.3 layer turns independent public-source records into a conservative evidence graph without treating name similarity as proof of legal identity or entitlement.

## Identity policy

The engine uses three evidence tiers:

1. **Exact public identifiers** — Companies House company numbers, patent numbers, and ISRCs. These create high-confidence canonical identifier nodes.
2. **Exact normalized names** — owner/entity names create conservative name nodes. A shared name across sources is a useful cross-source signal but is not treated as unique legal identity.
3. **Organization-name variants** — fuzzy similarity is organization-only and creates `possible_same_organization` relations requiring human review. Person-name fuzzy matching is disabled by design.

This keeps the graph useful for discovery while preventing automatic conclusions from common names or superficial similarity.

## Graph model

Tables:

- `entities` — canonical identifier/name nodes;
- `entity_memberships` — evidence linking an opportunity to an entity;
- `entity_relations` — co-occurrence and reviewable similarity edges.

An opportunity can belong to multiple entities. For example, one patent licensing notice can connect an organization-name entity and a patent-number entity. Another source that mentions the same patent or company number then creates a cross-source graph automatically.

## Commands

```bash
fia resolve
fia entities --min-sources 2
fia relations --min-confidence 0.9
fia graph 123
```

Disable organization fuzzy matching when testing deterministic joins only:

```bash
fia resolve --no-fuzzy
```

Tune candidate generation conservatively:

```bash
fia resolve --fuzzy-limit 10000 --min-fuzzy-score 0.93
```

## Companies House ingestion

With `COMPANIES_HOUSE_API_KEY` configured:

```bash
fia ingest companies-house-dissolved-search "example technology"
fia ingest companies-house-dissolved-range 2026-08-01 2026-08-14 --size 1000
fia resolve
```

Dissolved-company records become `dissolved_company` opportunities with the official company number retained in source evidence. This permits strong joins between dissolved-company records and other datasets that contain the same company number.

## API

```text
GET /api/entities
GET /api/entities/{entity_id}
GET /api/entity-relations
```

All outputs are intelligence/evidence. They do not establish ownership, entitlement, heirship, claim validity, or authority to contact a claimant.

## Scale behavior

Exact-identifier and exact-name node creation streams from SQLite and is not bounded by the fuzzy limit. Fuzzy organization-name candidate generation is explicitly bounded with `--fuzzy-limit`, and pathological blocks are skipped rather than creating quadratic match noise.
