# v1.3 — Source Discovery Mining

## Objective

Find *new source systems* before finding individual assets. FIA queries official data catalogs for metadata, normalizes candidate datasets, then ranks which source deserves integration work.

## Pipeline

```text
official catalog metadata
  -> keyword discovery queries
  -> normalized SourceCandidate
  -> cross-query dedupe
  -> source score
  -> monetization-route hypothesis
  -> analyst approve/watch/reject
  -> only then design an ingestion adapter
```

## Candidate score

The overall source score combines:

- asset density: how directly metadata points to unclaimed, surplus, liquidation, royalties, dormant assets, dissolved-company assets, patent licensing, auctions or procurement;
- machine readability: API/SPARQL/JSON/CSV score higher than PDF/HTML;
- access: public/read-only metadata is preferred;
- legal reuse: explicit open/public licenses score higher, but always require review;
- freshness: recently modified sources receive a higher discovery priority;
- novelty: low-popularity signals receive a small bonus where the catalog exposes usage/popularity; and
- monetization fit: routing hypothesis only, not authority to transact.

## Catalog boundary

The miner does not recursively download every resource linked by a catalog. It records metadata and requires an explicit analyst state transition before deeper integration.

## Candidate states

- `discovered`
- `approved`
- `watch`
- `rejected`
- `archived`

Rediscovery updates metadata and scoring without erasing that state.
